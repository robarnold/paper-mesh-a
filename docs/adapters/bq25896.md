# BQ25896 charger adapter

The [portable crate](../../crates/bq25896/README.md) separates charger observations from battery-isolation commands.
Firmware supplies the bus and coordinates consumers. The crate does not select an executor, polling interval, or system shutdown policy.

The chip-defined seven-bit I2C address is `0x6b`. Board wiring does not select it.
The bus supplies the direction bit. See the [BQ25896 datasheet, section 6](https://www.ti.com/lit/ds/symlink/bq25896.pdf).

## Observations

The [observation module](../../crates/bq25896/src/observation.rs) returns platform `ChargerState` values.
Callers hold the bus for the complete observation. A bus error discards the partial result.
Register pointer writes do not change charger configuration.
The adapter does not start ADC conversions or change charge limits, watchdog settings, or BATFET controls.

The adapter reads `REG0C` twice with separate transactions. The first read supplies latched faults and the second supplies current faults.
The thermistor field reports its current state in both reads. A read clears latched fault history.
The watchdog flag can indicate default mode after reset or watchdog expiry.
See datasheet sections 9.2.9.3 and 9.3 for fault behavior, and section 9.4 for register fields.

The configured input limit does not establish available supply current.
The reported source class does not identify the physical connector. Firmware must account for board wiring.
Charger ADC measurements remain unavailable because this adapter does not start or verify a conversion.

## Battery isolation

The separate [ship module](../../crates/bq25896/src/ship.rs) preserves the existing guarded isolation sequence.
`check` refuses isolation when live input, charger status, or boost configuration indicates an active supply.
It does not reserve that condition. `cut` checks it again immediately before the write.
The caller must stop consumers first and hold the bus across the complete sequence.

`cut` requests immediate BATFET isolation while preserving unrelated settings and clearing one-shot commands.
It attempts the write once. A successful return confirms the bus transaction, not loss of system power.
A bus error can leave hardware state uncertain. The runtime decides reset recovery and must not assume rollback.

`initialize` clears retained isolation commands and verifies the relevant BATFET controls before consumers start.
It does not perform general charger configuration. Cold start and reset recovery can use the same operation.
Firmware retains service preparation, external-power error mapping, shutdown deadlines, and system reset decisions.

## Verification limits

Native [observation tests](../../crates/bq25896/tests/observations.rs) cover decoding, fault history, and failure at each transaction.
Native [isolation tests](../../crates/bq25896/tests/ship.rs) cover supply changes, register preservation, uncertain access, and repeatable startup restoration.
The simulator retains an independent gauge-and-charger failure test.
These tests do not establish physical battery isolation, power-loss timing, or recovery on the board.
