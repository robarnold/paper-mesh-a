01 / COMPOSITION

One shell. Three pages.

The navigator manages transitions and return history. The shell supplies the frame. Each page owns its content and local state.

  1. Select Open Detail, then Count a tap.
  2. Select Back. Select Open Tools, then Open Detail. The count remains.
  3. Select Back. You return to Tools, which opened Detail.
  4. Open Detail again. Select Enter full screen. Use Hardware Home to exit.

Tap the device screen or expand Keyboard controls below it. With the preview focused, the Home key returns Home.

Navigator: launch and transitions

Launch one shell with the root identity and retained page collection. The platform navigator handles input dispatch, return history, and lifecycle callbacks.

Open records the caller. Back returns to that caller. Home returns to the root and clears history.

The shell draws the header, recognizes Back gestures, and clips page content. The navigator supplies the active page and return availability.

Page: one destination

A page supplies a title, presentation mode, and navigation availability. It handles local input and draws its content.

Keep page objects in the collection when their state must survive navigation. The navigator calls leave before enter. Pages do not declare parents.

Try the exceptions

  • Full screen: the header disappears. Hardware Home keeps its meaning.
  • Pending operation: start the example operation. Back becomes disabled and Home cannot leave. Select Finish operation to restore navigation.

The example reserves eight return entries. A full stack rejects Open without changing the active page.

This example has independent state and performs no device operations. Frames update immediately. It does not model display refresh timing.

02 / VISUAL LANGUAGE

Choose a purpose.

Start with four text roles. Controls select their own label styles. Use Body for status messages.

RoleUse it for
TitlePage and section names.
BodyInstructions, values, and status messages.
CaptionPage context and short group labels, such as PLATFORM UI and TEXT ROLES.
SecondarySupporting information.

Fonts, sizes, and weights

The device uses the built-in ASCII monospace bitmap fonts from embedded-graphics. Each character occupies a cell with a fixed width.

FontCell sizeWeightRoles
FONT_10X2010 × 20 pxFixed bitmapTitle, Body, Secondary
FONT_6X106 × 10 pxFixed bitmapCaption

Cell sizes give width × height in logical device pixels. The browser scales the preview to fit its frame.

Stroke weight is part of each bitmap. The current style has no bold variant or numeric weight setting.

Title and Body share the same font, size, and weight. Secondary uses a lighter color. Selected controls invert colors without changing font weight.

Use words to explain unavailable data, pending work, and failures. Grayscale supports the message.

Underline variants

Each text role has a normal and an underlined variant. Underline keeps the same font, size, weight, and color.

Use underline for short emphasis. An underline alone does not identify an action or explain status.

Tap a text role on the device screen. Tap Underline to compare its variants. The selection stays active when you change roles.

Use Style::text(role) for normal text and Style::underlined_text(role) for underlined text. The current fonts have no italic variant.

Bubbled text

Use a rounded badge for a short label or notification count. It grows with the text and adds padding on all sides.

The default style uses a black bubble with white text on a white page. The text keeps its role's font and size.

Tap Bubbled to compare the New, 3, 12, and 99+ samples. Try Caption for smaller badges. Underline also works inside a bubble.

TextBadge supplies this style in the platform toolkit. Its default padding is 8 px horizontally and 4 px vertically, with an 8 px corner radius.

Badges display information. Use a separate control for actions. The application supplies the label and decides when to hide or cap a count.

Give content room

Use the shared spacing profile for control insets and gaps. The application chooses its layout and viewport.

Tap Control gap or Section gap to compare their values and the space between the blocks.

Keep essential text within its assigned region. Add lines or pages when it does not fit.

Keep the palette small

Use named colors for foreground, background, supporting text, dividers, controls, and data. Selected controls use inverse text.

Tap a swatch to see its color role and grayscale value.
